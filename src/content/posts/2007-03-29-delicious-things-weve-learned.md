Auf der <a href="http://www.futureofwebdesign.com/pastevents.html">gleichen Konferenz</a> spricht Joshua Schachter, Gründer von <a href="http://del.icio.us/">Delicious</a> über <a href="/wp-content/uploads/Joshua Schachter - The Future of Web App.mp3">Dinge, die er bei der Erstellung seines bekannten Social-Bookmarking-Dienste gelernt hat <strong>(MP3)</strong>.</a>

Auch hier findet sich wieder eine <a href="http://strange.corante.com/archives/2006/02/08/fowa_things_weve_learned_joshua_schachter.php"><strong>Zusammenfassung</strong> des 40-Minuten Vortrags</a> im Netz.

Und auch hier geht es unter anderem wieder um das <strong>Thema URL-Design</strong>.

Die Punkte die Schachter <strong>ab Minute 16</strong> anspricht:
<ul>
	<li>URLs sollen die Art und Weise wiederspiegeln, wie eine Seite benutzt wird</li>
	<li>URL-Eingabefeld ist das erste, das Benutzer von der Seite sehen</li>
	<li>Nutzer kopieren sie herum in eMail, IM, Dokumenten</li>
	<li>keine Sessionkeys in der URL, keine IDs, keine “index.php”</li>
	<li>das sind Dinge, die nur von der Technik und nicht von den Benutzer benötigt werden und auch nur der Technik helfen, nicht dem Benutzer — den interessiert es nicht</li>
	<li>ugly</li>
	<li>erfahrene Benutzer navigieren mit Hilfe der URLs. In Delicious spart das sogar Funktionalität im HTML-Interface</li>
</ul>
Interessant auch unter dem Gesichtspunkt der Bedeutung von <strong>RSS</strong>: Delicious hat mehr RSS-Traffic als HTML-Anfragen. Entsprechend gutes Caching ist nötig.

Auch in diesem Vortrag wird im Übrigen die Bedeutung offener <strong>APIs</strong> angesprochen:

Meine Stichworte dazu:
<ul>
	<li>Entwickler brauchte API ohnehin um eigene Daten in das System zu laden und heraus zunehmen.</li>
	<li>“it really does help adaption” insb. für Early Adopter die über das Produkt sprechen und es viral bewerben</li>
	<li>Sicherheitsgefühl: API gibt die Gewissheit, dass man immer an seine Daten heran kommt</li>
	<li>Offline speichern von Daten (temporär)</li>
	<li>je offener eine API, desto mehr Leute benutzen sie — bei delicious XML</li>
	<li>Tonnen an Tools die die API nutzen</li>
</ul>
